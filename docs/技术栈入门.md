# 技术栈入门

这份文档不教你写全部代码，只帮你把项目里出现的名词和流程串起来：看到一个类、一个注解、一条命令时，知道它是干什么的。

---

## 0. 先看全局

这个项目做的事：

```
浏览器（HTML/CSS/JS）
   │  HTTP 请求（JSON）
   ▼
Spring Boot（接收请求、管理对象）
   │  调用
   ▼
LangChain4j（拼提示词、查资料、调模型）
   │  调用
   ▼
DeepSeek / OpenAI 兼容接口（真正生成文字）
   │  流式返回
   ▼
Spring Boot → 浏览器，边生成边显示
```

项目里最需要先搞懂的三块是：

1. **Maven**：项目怎么管理依赖、怎么编译打包；
2. **Spring Boot**：对象怎么被创建、HTTP 请求怎么进来；
3. **LangChain4j + Reactor**：怎么调大模型、怎么流式返回。

## 1. Java 基础之外多出来的东西

### 1.1 项目目录约定

```
src/main/java/        写 Java 代码
src/main/resources/   放配置、提示词、岗位资料、静态页面
src/test/java/        写测试
pom.xml               项目说明 + 依赖清单
```

包名（`package org.itanna...`）必须和文件夹层级一致，否则编译不过。

### 1.2 注解（Annotation）

Java 基础里很少用，这个项目到处都是。可以把它理解成**贴在类/方法上的标签**，框架看到标签就会做对应的事。

```java
@RestController   // 这个类是处理 HTTP 请求的
public class XxxController { ... }
```

注解本身不执行逻辑，是“给框架看的说明书”。

### 1.3 接口没有实现类

`CareerAgentService` 是一个接口，没有 `implements` 它的类，但代码能跑。原因是 LangChain4j 在启动时**动态生成了一个实现**（代理对象）。这是框架能力，不是 Java 语法错误。

## 2. Maven：依赖和构建

### 2.1 它解决什么问题

没有 Maven 时，你要手动下载 jar、放进 `lib`、配置 classpath。Maven 用 `pom.xml` 描述“我需要哪些库”，自动下载并管理版本。

### 2.2 `pom.xml` 里有什么

```xml
<groupId>org.itanna</groupId>
<artifactId>langchain4j-demo</artifactId>
<version>0.0.1-SNAPSHOT</version>

<dependencies>
    <dependency>
        <groupId>dev.langchain4j</groupId>
        <artifactId>langchain4j-spring-boot-starter</artifactId>
        <version>1.19.0-beta29</version>
    </dependency>
</dependencies>
```

- **坐标**：groupId + artifactId + version，唯一确定一个库；
- **依赖**：项目需要的库，Maven 会自动把“依赖的依赖”也下载下来；
- **starter**：一组常用依赖的打包，比如 `spring-boot-starter-web` 一次带入 Web 开发需要的东西。

### 2.3 生命周期（常用命令）

| 命令 | 作用 |
| --- | --- |
| `mvn clean` | 删除 `target/` 里的旧产物 |
| `mvn compile` | 编译 `src/main/java` |
| `mvn test` | 编译并运行测试 |
| `mvn package` | 打成 jar，放在 `target/` |
| `mvn spring-boot:run` | 直接启动应用 |

本项目用 Maven Wrapper：

```powershell
.\mvnw.cmd clean test
.\mvnw.cmd spring-boot:run
```

`mvnw` 的作用：**不用自己安装 Maven**，第一次运行会自动下载（需要联网）。

### 2.4 本地仓库

下载的 jar 存在本地仓库（默认 `~/.m2/repository`，可以在 Maven 的 `settings.xml` 里修改）。换项目时能复用，不用重复下载。

## 3. Spring Boot：把对象和 Web 管起来

### 3.1 它解决什么问题

- 创建对象：不用自己 `new`，交给 Spring 容器；
- 接收 HTTP：内置 Tomcat，写个方法就能对外提供接口；
- 读配置：`application.yaml` 里的值自动注入；
- 自动配置：加了 starter，很多默认配置不用写。

### 3.2 启动类

```java
@SpringBootApplication
public class Langchain4jDemoApplication {
    public static void main(String[] args) {
        SpringApplication.run(Langchain4jDemoApplication.class, args);
    }
}
```

`@SpringBootApplication` 会扫描本项目包下的类，把带 `@Component`、`@Service`、`@RestController` 等的类创建成对象。

### 3.3 Bean、IoC、依赖注入

- **Bean**：由 Spring 创建并管理的对象；
- **IoC（控制反转）**：对象的创建权从“你自己 new”交给 Spring；
- **依赖注入**：对象需要什么，Spring 通过构造器参数传进来。

本项目的例子：

```java
public CareerAgentController(CareerAgentService careerAgentService) {
    this.careerAgentService = careerAgentService;
}
```

Controller 没有 `new CareerAgentService`，Spring 发现构造器需要它，就自动把容器里的 Bean 传进来。

### 3.4 常用注解

| 注解 | 作用 |
| --- | --- |
| `@SpringBootApplication` | 启动类 |
| `@RestController` | 处理 HTTP，返回值直接写响应体 |
| `@RequestMapping` / `@PostMapping` | 路径和方法（GET/POST） |
| `@RequestBody` | 把请求体 JSON 转成对象 |
| `@Component` / `@Service` | 普通 Bean |
| `@Configuration` + `@Bean` | 在配置类里手动创建 Bean |
| `@ExceptionHandler` | 处理异常 |
| `@RestControllerAdvice` | 全局异常处理 |

### 3.5 内置 Tomcat 与静态页面

- Spring Boot 自带 Tomcat，启动后监听 8080；
- `src/main/resources/static/index.html` 会被自动映射到 `GET /`，所以浏览器能直接打开；
- 接口路径由 `@RequestMapping` 决定，本项目是 `POST /api/chat`。

### 3.6 配置文件

`application.yaml` 用缩进表示层级：

```yaml
langchain4j:
  open-ai:
    chat-model:
      base-url: https://api.deepseek.com
```

可以写固定值，也可以用 `${环境变量:默认值}` 读取环境变量。

### 3.7 常用目录职责

| 目录/包 | 职责 |
| --- | --- |
| `controller` | 接收 HTTP、校验参数 |
| `aiService` | 声明 AI 服务接口 |
| `config` | 创建 Bean（记忆等） |
| `rag` | 读资料、向量检索 |
| `dto` | 请求体 / 响应体对象 |

## 4. LangChain4j：Java 里调大模型

### 4.1 它是什么

一个 Java 的大模型应用框架，帮你做这些事：

- 调模型（普通 / 流式）；
- 管理对话记忆；
- 检索本地资料（RAG）；
- 把“接口”自动变成可调用的 AI 服务。

### 4.2 两种模型

| 类型 | 特点 | 本项目 |
| --- | --- | --- |
| `ChatModel` | 一次性返回完整回答 | `chat-model` |
| `StreamingChatModel` | 边生成边返回片段 | `streaming-chat-model` |

返回 `Flux<String>` 的接口用的是流式模型。

### 4.3 `@AiService`：接口自动变成实现

```java
@AiService
public interface CareerAgentService {
    @SystemMessage(fromResource = "system.txt")
    Flux<String> chat(@MemoryId String memoryId, @UserMessage String message);
}
```

- `@SystemMessage`：系统提示词，管“角色和规则”；
- `@UserMessage`：用户消息；
- `@MemoryId`：哪一段对话；
- 框架启动时生成代理对象，Controller 注入的就是这个代理。

### 4.4 对话记忆

- `ChatMemoryStore`：存历史消息（本项目用内存版）；
- `ChatMemoryProvider`：按 `memoryId` 创建记忆窗口；
- `MessageWindowChatMemory`：只保留最近 N 条。

所以同一个 `memoryId` 能记住上文，不同 `memoryId` 互不影响；应用重启内存清空。

### 4.5 RAG（检索增强）

流程：

```
本地资料 → 分段 → 每段转成向量 → 存进向量库
用户问题 → 转成向量 → 找最相似的几段 → 拼进提示词 → 模型回答
```

相关名词：

- **embedding**：把文字变成一串数字（向量），语义相近的文字向量也相近；
- **向量库**：存这些向量，支持“找最相似”；
- **chunk（分段）**：把长资料切成小段，检索更精准；
- **Top-K**：取最相似的 K 段（本项目 `maxResults(5)`）；
- **ContentRetriever**：LangChain4j 的检索接口，本项目用向量检索实现。

## 5. Reactor / Flux：流式返回

### 5.1 为什么不是 String

普通接口：

```java
String answer = 模型.chat(...);   // 等全部生成完才返回
```

流式接口：

```java
Flux<String> answer = 模型.chatStream(...);  // 每生成一小段就发一个元素
```

`Flux` 是 Reactor 里的“0 到 N 个元素的异步序列”，可以理解成“会陆续到来的多个 String”。

### 5.2 前端怎么接

```js
const reader = response.body.getReader();
while (true) {
    const { done, value } = await reader.read();
    if (done) break;
    text += decoder.decode(value, { stream: true });
}
```

后端写一段，前端读一段，所以能看到“打字机效果”。

### 5.3 错误处理

流开始后 HTTP 状态码已经发出，不能再改成 500，所以用：

```java
.onErrorResume(error -> Flux.just("中文错误提示"))
```

把错误变成一段正文继续发出去。

## 6. 本项目一次请求的完整链路

1. 浏览器点“发送”，`fetch POST /api/chat`，带 `memoryId`、`message`、`profile`；
2. Spring MVC 把 JSON 转成 `ChatRequest`（含 `StudentProfile`）；
3. `CareerAgentController` 校验参数、把档案拼成文本；
4. `CareerAgentService`（代理）按 `memoryId` 取历史；
5. `ContentRetriever`（`RagConfig`）把问题向量化，取最相关的 5 段资料；
6. 资料拼进用户消息，连同 `system.txt` 一起发给 DeepSeek；
7. 模型流式返回，Controller 原样写给浏览器；
8. 前端边读边显示，结束后把整段回答存进 `localStorage`。

## 7. 术语表

| 术语 | 通俗解释 |
| --- | --- |
| Bean | 由 Spring 创建和管理的对象 |
| 依赖注入 | 需要什么，Spring 通过构造器给你 |
| starter | 一组依赖的打包 |
| 代理对象 | 框架动态生成的实现类 |
| embedding | 把文字变成向量（数字数组） |
| 向量库 | 存向量并支持相似度搜索 |
| chunk | 长资料切出来的小段 |
| Top-K | 取最相似的 K 条 |
| RAG | 先查资料再让模型回答 |
| Flux | 会陆续到来的多个值（流） |
| memoryId | 一段对话的标识 |

## 8. 建议的学习顺序

1. 先跑通项目，改 `system.txt` 看回答变化；
2. 改 `content/jobs/*.txt`，看检索结果变化；
3. 读 `CareerAgentController` → `CareerAgentService` → `RagConfig`；
4. 再补 Maven 生命周期和 Spring 注解；
5. 最后看 Reactor 的 `Flux` 和 LangChain4j 官方文档。

遇到看不懂的注解，先问“它是给谁看的标签”，再去查它的作用，比从头读框架源码高效得多。
