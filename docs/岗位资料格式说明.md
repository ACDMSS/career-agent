# 岗位资料格式说明

本文件放在 `docs/` 下，**不会被应用加载**。应用只读取 `src/main/resources/content/jobs/` 下的 `.txt` 文件。

## 只有两条规则

1. **第一段**（第一个空行之前）作为公共头，建议写岗位名称、公司、来源、日期；
2. **其余内容按空行分段**，每段单独参与检索；公共头会自动拼到每段前面。

所以段落之间记得空一行；一段太长会整段作为一条资料。

## 示例

```text
岗位名称：Java 后端开发工程师
公司：某公司
来源：https://原始链接
日期：2026-10-23

岗位职责
参与业务系统后端模块的设计与开发，按需求完成接口、数据处理和联调。

任职要求
熟悉 Java 基础，熟悉 Spring Boot 与 MySQL。

加分项
了解缓存、消息队列，有完整项目经历。
```

加载结果：

- 公共头 = 前面 4 行；
- 3 段正文（岗位职责、任职要求、加分项）；
- 每段交给模型时，都会带上公共头。

## 一个文件放多个岗位

用单独一行 `====`（四个等号以上）分隔，每个岗位各自的第一段就是它自己的公共头：

```text
岗位名称：岗位A
来源：来源A

岗位职责
……

====

岗位名称：岗位B
来源：来源B

岗位职责
……
```

不加 `====` 时，整个文件视为一个岗位。

## 注意事项

1. 文件编码用 **UTF-8**，否则中文会乱码。
2. 只录入可核对的内容，不要伪造公司、薪资、链接或日期；示例资料请明确标注“教学示例（非真实企业）”。
3. 第一段不放正文内容，只放来源信息，这样每段引用时都完整。
4. 每个文件至少需要两段（一段来源 + 一段正文），否则启动时会直接报错，不会静默跳过。
